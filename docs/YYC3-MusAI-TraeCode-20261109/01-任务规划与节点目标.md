# 任务规划与节点目标

> 总原则：执行有规划，规划有节点，节点有目标，目标可评估。

## 一、总体目标

在代码质量门禁已达标（1,388 Vitest + 121 Deno 用例、四维覆盖 ≥80%）的基础上，收口生产链路与发布链路，再把音乐项目沉淀为「UI 组件库 + 智能前端框架 + 知识库」三层可复用资产。

## 二、阶段划分

| 阶段 | 名称 | 目标 | 关闭标准 | 状态 |
| --- | --- | --- | --- | --- |
| Phase 0 | 生产就绪收口 | 漏洞清零、发布闭环、文档体系 | 审计 0 高危；`npm pack` 可验；日志/衔接文档落盘 | ✅ 4/5（Supabase 阻塞） |
| Phase 1 | UI 组件库产品化 | 组件文档站与质量门禁 | 组件示例页 + axe 0 serious | ⬜ |
| Phase 2 | 智能前端框架产品化 | Provider/语音/Prompt 契约 | 组件零直接 fetch，契约测试通过 | ⬜ |
| Phase 3 | 知识库产品化 | 文档站 + front matter CI | 站点可构建、死链 0、合规率 ≥95% | ⬜ |
| Phase 4 | 音乐场景全维度补全 | E2E/性能/数据治理 | 关键旅程 100%，Lighthouse ≥90 | ⬜ |
| Phase 5 | 发布与运营 | changesets + 监控 | 发布即验证，可回滚 | ⬜ |

## 三、Phase 0 任务分解

### Task 0.1: 会话文档体系

- 目标：按《YYC³ 团队通用 AI 协同开发文档》建立 00–04 文档与时刻衔接机制。
- 验收：目录、命名、YAML 标头、日志实时更新规则齐备。
- 完成标记：✅

### Task 0.2: 依赖漏洞清零

- 目标：升级 vitest / @vitest/coverage-v8 / tinypool / glob / minimatch / prismjs。
- 验收：`pnpm audit --audit-level=high`（官方 registry）退出码 0；全量测试仍通过。
- 风险：vitest 3 → 4 属大版本，需回归 1,388 用例。
- 完成标记：✅

### Task 0.3: 包说明与元数据

- 目标：15 个公开包 README + 根 CHANGELOG / SECURITY / CONTRIBUTING。
- 验收：`npm pack --dry-run` 每包含 dist + README。
- 完成标记：⬜

### Task 0.4: 发布流水线

- 目标：`.github/workflows/publish.yml`，build → pack 校验 → changesets publish → registry 安装冒烟。
- 验收：无 `NPM_TOKEN` 时 dry-run 全绿；有 token 时可发布预发布版本。
- 完成标记：⬜

### Task 0.5: 后端真实链路

- 目标：Supabase 连接清单 + 健康检查脚本 + 文档。
- 验收：无凭据时脚本明确报「未配置」而非伪造通过。
- 完成标记：⬜
