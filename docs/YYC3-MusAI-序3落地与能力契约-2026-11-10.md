# 序 3 落地与能力契约

## 一、决策记录

| 优先级 | 事项 | 决策 | 依据 | 影响 |
| --- | --- | --- | --- | --- |
| P0 | 本地模式 | 方案 B：吸收契约、重写实现 | 历史实现 824 行无测试；契约要随包发布，不能带历史包袱 | `apiFetch` 具备降级能力，所有调用方自动受益 |
| P1 | 打拍算法 | 方案 B：算法下沉、UI 后置 | 已有 `parseLrc` 缺生成侧；编辑器当前无消费入口 | 补齐歌词生成闭环，纯函数可测 |
| P2 | 打拍编辑器 | 按需启动 | 无使用场景时造 UI 即无人调用 | 满足触发条件再立项 |
| — | 主题系统 | 不吸收 | 与 `music-design-tokens` 重叠，两套 `applyTheme` 会导致主题分叉 | 差异项（自定义主题持久化）单独立项评估 |

P2 触发条件（三条同时满足才启动）：

1. 应用内出现歌词制作/校准入口；
2. 需要可视化波形或录制联动；
3. 至少 2 个消费方复用同一编辑器。

## 二、P0 本地模式契约

文件：`packages/music-utils/src/localMode.ts`

```ts
isLocalMode(): boolean
setLocalMode(enabled: boolean): void
localApiFetch<T>(path: string, init?: RequestInit & { signal?: AbortSignal }): Promise<T | null>
getLocalStats(): { entries: number; bytes: number; keys: string[]; mode: boolean }
clearLocalData(): void
```

存储约定：

- 键前缀统一 `yyc3:music:local:`，开关独立键 `yyc3:music:local:mode`，不得散写魔法字符串；
- 无 `localStorage` 环境（SSR / Node 测试）用内存 Map 兜底；
- 损坏 JSON 视为未命中，不抛异常。

`localApiFetch` 语义：

| 方法 | 行为 |
| --- | --- |
| GET | 读缓存，未命中返回 `null` |
| POST / PUT / PATCH | 写入缓存并返回 `{ ...body, id }`；id 由 path 派生，重复写幂等 |
| DELETE | 删除并返回 `{ success: true }`，不存在同样成功 |
| 任意 | 已中止的 signal 抛 `AbortError`，不静默返回 |

### 2.1 降级规则（`apiFetch`）

| 场景 | 行为 |
| --- | --- |
| `isLocalMode()` 为 true | 完全走本地，零网络请求 |
| 远程 5xx / 429 | 有缓存返回缓存，无缓存返回 `null` |
| 远程 4xx | **不降级**，返回 `null`（确定性客户端错误不能被缓存掩盖） |
| 非 JSON 响应 | 尝试本地缓存 |
| 主动中止 | 不降级，保持既有 `null` 控制流 |
| `apiFetchStrict` | 永不降级，失败照旧抛 `ApiError` |

### 2.2 接入方式

无后端的宿主在启动时调用一次 `setLocalMode(true)` 即获得完整离线读写；未调用时保持原有「无后端返回 null」的兼容行为（既有测试仍要求该语义）。

## 三、P1 打拍算法

文件：`packages/music-lyrics/src/tapSync.ts`

```ts
normalizeTaps(taps: number[], minGapMs = 120): number[]
assignTimestamps(lines: string[], taps: number[], options?: { offsetMs?: number; pad?: boolean }): LrcLine[]
serializeLrc(lines: LrcLine[], metadata?: Partial<LrcMetadata>): string
```

- `normalizeTaps`：过滤非有限数与负数、升序、丢弃小于 `minGapMs` 的抖动点。
- `assignTimestamps`：拍点与歌词行等量映射；拍点不足按平均间隔补齐（`pad: false` 时 `time` 为 `null`）；拍点过多忽略；`offsetMs > 0` 表示整体提前并钳制到 0，与 `parseLrc` 的 offset 语义一致。
- `serializeLrc`：输出 `[mm:ss.xx]`；metadata 顺序稳定；`time` 为 null 的行跳过；写出 `[offset:]` 时反向加回，保证「序列化 → 解析」时间还原（误差 ≤5ms）。

## 五、已知边界

- 本地模式只覆盖 `localStorage`，容量上限约 5MB，大数据集需后续评估 IndexedDB；
- 只做缓存与降级，不做冲突合并与同步队列；
- 打拍算法不理解音频波形，时间点由调用方给出；
- UI 编辑器不在本仓库，P2 触发前不实现。
