## 1. 评估概述

### 1.1 评估目标

本评估旨在为YYC³项目提供准确的存储容量规划，包括：

- 预测未来3年的数据增长趋势
- 制定分阶段的存储扩容计划
- 优化存储资源配置
- 建立存储监控告警机制

### 1.2 评估方法

采用**多层次评估法**：

| 评估层次 | 方法 | 数据来源 |
|---------|-----|---------|
| 表级评估 | 单表数据量 × 增长率 | 业务需求文档 |
| 模块级评估 | 关联表聚合分析 | 数据模型文档 |
| 全局评估 | 整体趋势预测 | 历史数据推演 |

### 1.3 时间范围

| 阶段 | 时间范围 | 评估重点 |
|-----|---------|---------|
| 短期 | 0-6个月 | 初始容量规划 |
| 中期 | 6-24个月 | 增长趋势预测 |
| 长期 | 24-36个月 | 极限容量评估 |

## 3. 存储增长趋势分析

### 3.1 增长模型

采用**复合增长模型**预测存储需求：

```
Storage(t) = Base × (1 + GrowthRate)^t
```

其中：
- Base: 基础存储量
- GrowthRate: 月增长率
- t: 月数

### 3.2 关键表增长率

| 表名 | 预期月增长率 | 主要驱动因素 |
|-----|-------------|-------------|
| core.users | 15-20% | 新用户注册 |

| core.messages | 25-30% | AI使用增长 |
| core.audit_logs | 15-20% | 活跃度提升 |

#### 4.2.2 数据归档策略

```sql
-- 创建归档表
CREATE TABLE core.messages_archive (
    LIKE core.messages INCLUDING ALL
);

-- 归档90天前的数据
CREATE OR REPLACE FUNCTION core.archive_old_messages()
RETURNS INTEGER AS $$
DECLARE
    archived_count INTEGER;
BEGIN
    WITH archived AS (
        DELETE FROM core.messages
        WHERE created_at < CURRENT_DATE - INTERVAL '90 days'
        RETURNING *
    )
    INSERT INTO core.messages_archive
    SELECT * FROM archived;
    
    GET DIAGNOSTICS archived_count = ROW_COUNT;
    RETURN archived_count;
END;
$$ LANGUAGE plpgsql;

-- 定时执行归档
SELECT cron.schedule(
    'archive-messages',
    '0 2 * * *',
    $$SELECT core.archive_old_messages()$$
);
```

## 6. 监控与告警

### 6.1 存储监控指标

```python
class StorageMonitor:
    def collect_storage_metrics(self):
        metrics = self.db.execute("""
            SELECT 
                schemaname,
                tablename,
                pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) as total_size,
                pg_size_pretty(pg_relation_size(schemaname||'.'||tablename)) as table_size,
                pg_size_pretty(pg_indexes_size(schemaname||'.'||tablename)) as index_size,
                pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename) - 
                              pg_relation_size(schemaname||'.'||tablename) - 
                              pg_indexes_size(schemaname||'.'||tablename)) as toast_size
            FROM pg_tables
            WHERE schemaname = 'core'
            ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC
        """)
        return metrics
    
    def check_storage_usage(self):
        usage = self.db.execute("""
            SELECT 
                pg_size_pretty(pg_database_size(current_database())) as db_size,
                (pg_database_size(current_database)::float / 
                 (SELECT setting::bigint FROM pg_settings WHERE name = 'max_pages_per_relation')::float * 
                 current_setting('block_size')::bigint) * 100 as usage_percent
        """)
        return usage
```

### 6.3 存储增长预测

```sql
-- 创建存储增长预测函数
CREATE OR REPLACE FUNCTION admin.predict_storage_growth(
    p_months_ahead INTEGER DEFAULT 6
) RETURNS TABLE(
    table_name TEXT,
    current_size BIGINT,
    predicted_size BIGINT,
    growth_percent NUMERIC
) AS $$
DECLARE
    v_growth_rate NUMERIC;
BEGIN
    -- 查询最近30天的增长率
    SELECT AVG(growth_rate) INTO v_growth_rate
    FROM (
        SELECT 
            schemaname,
            tablename,
            (
                pg_total_relation_size(schemaname||'.'||tablename) - 
                LAG(pg_total_relation_size(schemaname||'.'||tablename)) OVER (
                    PARTITION BY schemaname, tablename 
                    ORDER BY check_time
                )
            ) * 100.0 / NULLIF(
                LAG(pg_total_relation_size(schemaname||'.'||tablename)) OVER (
                    PARTITION BY schemaname, tablename 
                    ORDER BY check_time
                ), 0
        ) as growth_rate
        FROM admin.storage_history
        WHERE check_time >= CURRENT_DATE - INTERVAL '30 days'
    ) growth_data;
    
    RETURN QUERY
    SELECT 
        t.schemaname || '.' || t.tablename as table_name,
        pg_total_relation_size(t.schemaname||'.'||t.tablename) as current_size,
        pg_total_relation_size(t.schemaname||'.'||t.tablename) * 
            POWER(1 + v_growth_rate / 100.0, p_months_ahead) as predicted_size,
        v_growth_rate * p_months_ahead as growth_percent
    FROM pg_tables t
    WHERE t.schemaname = 'core';
END;
$$ LANGUAGE plpgsql;
```
