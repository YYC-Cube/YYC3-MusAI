## 1. 规划概述

### 1.1 规划目标

通过科学的连接数规划，实现以下目标：

- **最大化并发性能**: 在资源限制下支持最大并发请求
- **优化资源利用**: 平衡连接数与系统资源使用
- **保障系统稳定性**: 防止连接数过多导致系统崩溃
- **提升用户体验**: 减少连接等待时间，提高响应速度

### 1.2 核心原则

| 原则 | 说明 | 实施要点 |
|-----|-----|---------|
| 按需分配 | 根据实际业务需求配置连接数 | 分析业务模式，峰值预测 |
| 资源平衡 | 连接数与系统资源匹配 | 考虑CPU、内存、磁盘I/O |
| 分层管理 | 不同场景使用不同连接池 | 读写分离、业务分离 |
| 监控告警 | 实时监控连接使用情况 | 设置阈值，及时告警 |
| 动态调整 | 根据负载动态调整连接数 | 使用连接池中间件 |

### 1.3 规划范围

| 层级 | 连接类型 | 配置范围 |
|-----|---------|---------|
| 应用层 | 应用连接池 | 10-100/实例 |
| 中间件层 | PgBouncer连接池 | 100-1000 |
| 数据库层 | PostgreSQL最大连接数 | 200-500 |

## 2. 业务连接需求分析

### 2.1 业务场景分析

#### 2.1.1 Web应用连接

**特点**:
- 短连接，频繁建立和断开
- 读多写少（约8:2）
- 对延迟敏感
- 并发量高

**连接需求**:

| 指标 | 数值 | 说明 |
|-----|-----|------|
| 日活用户 (DAU) | 50,000 | 每日活跃用户数 |
| 峰值并发用户 | 5,000 | 同时在线用户 |
| 平均会话时长 | 10分钟 | 用户平均在线时间 |
| 平均请求间隔 | 5秒 | 用户请求间隔 |

**连接数计算**:

```
峰值连接数 = 峰值并发用户 × 请求间隔 / 响应时间
           = 5,000 × 5s / 0.1s
           = 250,000 连接

考虑连接池复用（复用率20%）：
实际需要连接数 = 250,000 × 0.2 = 50,000 连接
```

#### 2.1.2 API服务连接

**特点**:
- 长连接，保持连接池
- 读写均衡（约5:5）
- 对吞吐量要求高
- 并发量中等

**连接需求**:

| 指标 | 数值 | 说明 |
|-----|-----|------|
| API实例数 | 20 | 后端服务实例 |
| 每实例连接池大小 | 50 | 每个实例的连接池 |
| 峰值QPS | 10,000 | 每秒请求数 |
| 平均响应时间 | 50ms | API响应时间 |

**连接数计算**:

```
总连接数 = API实例数 × 每实例连接池大小
        = 20 × 50
        = 1,000 连接

考虑连接池复用（复用率50%）：
实际需要连接数 = 1,000 × 0.5 = 500 连接
```

#### 2.1.3 后台任务连接

**特点**:
- 长连接，执行批量操作
- 写多读少（约7:3）
- 对吞吐量要求高
- 并发量低

**连接需求**:

| 指标 | 数值 | 说明 |
|-----|-----|------|
| 任务类型 | 5 | 数据同步、报表生成等 |
| 每任务并发数 | 10 | 每种任务的并发数 |
| 任务执行时长 | 1-10分钟 | 任务平均执行时间 |

**连接数计算**:

```
总连接数 = 任务类型数 × 每任务并发数
        = 5 × 10
        = 50 连接
```

### 2.2 总连接需求汇总

| 业务类型 | 峰值连接数 | 平均连接数 | 优先级 |
|---------|-----------|-----------|-------|
| Web应用 | 50,000 | 10,000 | ⭐⭐⭐⭐⭐ |
| API服务 | 1,000 | 500 | ⭐⭐⭐⭐ |
| 后台任务 | 50 | 20 | ⭐⭐⭐ |
| 监控系统 | 100 | 50 | ⭐⭐ |
| **总计** | **51,150** | **10,570** | - |

**结论**: 使用连接池中间件后，实际需要连接数可降至500-1000。

#### 4.2.2 自动处理脚本

```python
#!/usr/bin/env python3
import psycopg2
import subprocess
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

class ConnectionManager:
    def __init__(self, connection_string):
        self.conn = psycopg2.connect(connection_string)
        
    def check_long_running_queries(self, threshold_seconds=300):
        query = """
            SELECT pid, usename, query_start, query
            FROM pg_stat_activity
            WHERE state = 'active'
            AND EXTRACT(EPOCH FROM (now() - query_start)) > %s
            ORDER BY query_start
        """
        cursor = self.conn.cursor()
        cursor.execute(query, (threshold_seconds,))
        long_queries = cursor.fetchall()
        
        if long_queries:
            logger.warning(f"发现 {len(long_queries)} 个长时间运行的查询")
            for pid, username, query_start, query in long_queries:
                logger.warning(f"PID: {pid}, User: {username}, Duration: {query_start}")
                
        return long_queries
    
    def kill_idle_in_transaction(self, threshold_minutes=5):
        query = """
            SELECT pid, usename, state_change, query
            FROM pg_stat_activity
            WHERE state = 'idle in transaction'
            AND EXTRACT(EPOCH FROM (now() - state_change)) > %s
        """
        cursor = self.conn.cursor()
        cursor.execute(query, (threshold_minutes * 60,))
        idle_trans = cursor.fetchall()
        
        if idle_trans:
            logger.warning(f"发现 {len(idle_trans)} 个长时间空闲事务")
            for pid, username, state_change, query in idle_trans:
                try:
                    kill_query = f"SELECT pg_terminate_backend({pid})"
                    cursor.execute(kill_query)
                    logger.info(f"已终止空闲事务 PID: {pid}")
                except Exception as e:
                    logger.error(f"终止空闲事务失败 PID: {pid}, Error: {e}")
                    
        return idle_trans
    
    def check_connection_pool_health(self):
        query = """
            SELECT 
                count(*) as total_connections,
                count(*) FILTER (WHERE state = 'active') as active,
                count(*) FILTER (WHERE state = 'idle') as idle,
                count(*) FILTER (WHERE state = 'idle in transaction') as idle_in_trans
            FROM pg_stat_activity
            WHERE datname = 'yyc3_aify'
        """
        cursor = self.conn.cursor()
        cursor.execute(query)
        result = cursor.fetchone()
        
        total, active, idle, idle_in_trans = result
        logger.info(f"连接状态 - 总数: {total}, 活跃: {active}, 空闲: {idle}, 空闲事务: {idle_in_trans}")
        
        return {
            'total': total,
            'active': active,
            'idle': idle,
            'idle_in_trans': idle_in_trans
        }
    
    def get_pg_bouncer_stats(self):
        try:
            result = subprocess.run(
                ['psql', '-h', 'localhost', '-p', '6432', '-U', 'pgbouncer', '-d', 'pgbouncer', '-c', 'SHOW POOLS;'],
                capture_output=True,
                text=True
            )
            logger.info(f"PgBouncer连接池状态:\n{result.stdout}")
            return result.stdout
        except Exception as e:
            logger.error(f"获取PgBouncer状态失败: {e}")
            return None

if __name__ == '__main__':
    conn_str = "host=localhost port=5433 dbname=yyc3_aify user=yyc3_admin"
    manager = ConnectionManager(conn_str)
    
    # 检查连接池健康状态
    manager.check_connection_pool_health()
    
    # 检查长时间运行的查询
    manager.check_long_running_queries(threshold_seconds=300)
    
    # 检查并清理空闲事务
    manager.kill_idle_in_transaction(threshold_minutes=5)
    
    # 获取PgBouncer状态
    manager.get_pg_bouncer_stats()
```

### 4.3 连接池优化

#### 4.3.1 连接池大小调优

```python
def calculate_optimal_pool_size(
    target_utilization=0.8,
    avg_query_time_ms=50,
    target_throughput_qps=1000
):
    """
    计算最优连接池大小
    
    参数:
        target_utilization: 目标CPU利用率 (0-1)
        avg_query_time_ms: 平均查询时间（毫秒）
        target_throughput_qps: 目标吞吐量（QPS）
    
    返回:
        optimal_pool_size: 最优连接池大小
    """
    # Little's Law: L = λ * W
    # L = 并发请求数 (连接池大小)
    # λ = 请求到达率 (QPS)
    # W = 平均服务时间 (查询时间)
    
    # 考虑CPU利用率
    optimal_pool_size = (target_throughput_qps * avg_query_time_ms / 1000) / target_utilization
    
    return int(optimal_pool_size)

# 示例计算

    target_utilization=0.8,
```

```python
                cursor = conn.cursor()
                cursor.execute("SELECT 1")
                cursor.close()
                print("连接创建成功")
                return conn

                print(f"连接创建失败: {e}")
                return None
        
        # 使用线程池并发创建连接
        with ThreadPoolExecutor(max_workers=self.pool_size) as executor:
            futures = [executor.submit(create_connection) for _ in range(self.pool_size)]
            connections = [f.result() for f in futures if f.result() is not None]
        
        print(f"连接池预热完成，实际创建连接数: {len(connections)}")
        
        # 关闭连接（实际应用中应保留在连接池中）
        for conn in connections:
            conn.close()
            
        return len(connections)
```

```bash
#!/bin/bash
# emergency_connection_handler.sh

# 配置
MAX_CONNECTIONS=500
CRITICAL_THRESHOLD=450
LOG_FILE="/var/log/postgresql/emergency_handler.log"

# 记录日志
log() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" >> $LOG_FILE
}

# 检查当前连接数
check_connection_count() {
    local count=$(psql -h localhost -p 5433 -U yyc3_admin -d yyc3_aify -t -c "
        SELECT count(*) FROM pg_stat_activity WHERE datname = 'yyc3_aify'
    ")
    echo $count
}

# 终止非关键连接
terminate_non_critical_connections() {
    local query="
        SELECT pid
        FROM pg_stat_activity
        WHERE datname = 'yyc3_aify'
        AND usename NOT IN ('yyc3_admin', 'postgres')
        AND state = 'idle'
        ORDER BY state_change DESC
        LIMIT 10
    "
    
    local pids=$(psql -h localhost -p 5433 -U yyc3_admin -d yyc3_aify -t -c "$query")
    
    if [ -n "$pids" ]; then
        for pid in $pids; do
            psql -h localhost -p 5433 -U yyc3_admin -d yyc3_aify -c "SELECT pg_terminate_backend($pid)" > /dev/null 2>&1
            log "已终止非关键连接 PID: $pid"
        done
    fi
}

    echo $message >> $LOG_FILE
}

if [ $current_count -ge $MAX_CONNECTIONS ]; then

    terminate_non_critical_connections
    send_alert $current_count
elif [ $current_count -ge $CRITICAL_THRESHOLD ]; then
    log "警告: 连接数接近临界值"
```

```python
def calculate_optimal_pool_size(
    cpu_cores=32,
    avg_query_time_ms=50,
    target_throughput_qps=1000
):
    """
    计算最优连接池大小
    
    参数:
        cpu_cores: CPU核心数
        avg_query_time_ms: 平均查询时间（毫秒）
        target_throughput_qps: 目标吞吐量（QPS）
    """
    # 方法1: 基于CPU核心数
    pool_size_by_cpu = cpu_cores * 2 + 1
    
    # 方法2: 基于吞吐量
    pool_size_by_throughput = (target_throughput_qps * avg_query_time_ms / 1000) / 0.8
    
    # 取两者的较小值
    optimal_size = min(pool_size_by_cpu, pool_size_by_throughput)
    
    return int(optimal_size)

# 示例

    cpu_cores=32,
    avg_query_time_ms=50,
    target_throughput_qps=1000
)
```
