## 一、核心业务领域

### 1.1 用户域 (User Domain)

| 表名 | 用途 | 关键字段 | 业务规则 |
|------|------|----------|----------|
| `users` | 用户基础信息 | id, username, email, status | 用户名唯一、邮箱唯一 |
| `user_profiles` | 用户详细资料 | user_id, full_name, avatar, bio | 与users 1:1关系 |
| `user_preferences` | 用户偏好设置 | user_id, language, theme | 与users 1:1关系 |

### 1.2 会话域 (Conversation Domain)

| 表名 | 用途 | 关键字段 | 业务规则 |
|------|------|----------|----------|
| `conversations` | 对话会话 | id, user_id, title, model | 一个用户可有多个会话 |
| `messages` | 消息记录 | id, conversation_id, role, content | 消息属于单个会话 |
| `message_tokens` | Token统计 | message_id, tokens, cost | 与messages 1:1关系 |

### 1.3 权限域 (Permission Domain)

| 表名 | 用途 | 关键字段 | 业务规则 |
|------|------|----------|----------|
| `roles` | 角色定义 | id, name, description | 角色名称唯一 |
| `permissions` | 权限定义 | id, resource, action | 资源+动作唯一 |
| `role_permissions` | 角色权限关联 | role_id, permission_id | 多对多关系 |
| `user_roles` | 用户角色关联 | user_id, role_id | 多对多关系 |

### 1.4 审计域 (Audit Domain)

| 表名 | 用途 | 关键字段 | 业务规则 |
|------|------|----------|----------|
| `audit_logs` | 操作审计 | id, user_id, action, entity | 记录所有敏感操作 |
| `api_logs` | API调用日志 | id, endpoint, method, status_code | 记录API请求响应 |

### 1.5 配置域 (Configuration Domain)

| 表名 | 用途 | 关键字段 | 业务规则 |
|------|------|----------|----------|
| `system_configs` | 系统配置 | key, value, description | key唯一 |
| `feature_flags` | 功能开关 | flag_name, is_enabled | 控制功能启用状态 |

## 三、数据字典

### 3.1 核心表字段定义

#### users 表
```sql
CREATE TABLE core.users (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    username        VARCHAR(50) UNIQUE NOT NULL,
    email           VARCHAR(255) UNIQUE NOT NULL,
    password_hash   VARCHAR(255) NOT NULL,
    full_name       VARCHAR(100),
    status          VARCHAR(20) DEFAULT 'active',
    email_verified  BOOLEAN DEFAULT FALSE,
    last_login_at   TIMESTAMPTZ,
    created_at      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    
    CONSTRAINT chk_status CHECK (status IN ('active', 'inactive', 'suspended', 'deleted'))
);
```

#### conversations 表
```sql
CREATE TABLE core.conversations (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID        NOT NULL REFERENCES core.users(id) ON DELETE CASCADE,
    title           VARCHAR(255) NOT NULL,
    model           VARCHAR(50) NOT NULL,
    context         JSONB,
    metadata        JSONB,
    created_at      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_user_id (user_id),
    INDEX idx_created_at (created_at DESC)
);
```

#### messages 表
```sql
CREATE TABLE core.messages (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID        NOT NULL REFERENCES core.conversations(id) ON DELETE CASCADE,
    role            VARCHAR(20) NOT NULL,
    content         TEXT        NOT NULL,
    tokens          INTEGER,
    cost            DECIMAL(10,6),
    metadata        JSONB,
    created_at      TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    
    CONSTRAINT chk_role CHECK (role IN ('system', 'user', 'assistant')),
    INDEX idx_conversation_id (conversation_id),
    INDEX idx_created_at (created_at DESC)
);
```

### 3.2 字段命名规范

| 类型 | 命名规则 | 示例 |
|------|----------|------|
| 主键 | `id` (UUID) | `gen_random_uuid()` |
| 外键 | `{table}_id` | `user_id`, `conversation_id` |
| 时间戳 | `{event}_at` | `created_at`, `updated_at` |
| 布尔值 | `is_{attribute}` | `is_active`, `is_verified` |
| 枚举 | 使用CHECK约束 | `status IN (...)` |

## 四、业务规则与约束

### 4.1 数据完整性约束

```sql
-- 用户状态机
ALTER TABLE core.users ADD CONSTRAINT chk_user_status 
    CHECK (status IN ('pending', 'active', 'inactive', 'suspended', 'deleted'));

-- 消息角色约束
ALTER TABLE core.messages ADD CONSTRAINT chk_message_role 
    CHECK (role IN ('system', 'user', 'assistant', 'tool'));

-- Token成本非负
ALTER TABLE core.messages ADD CONSTRAINT chk_cost_non_negative 
    CHECK (cost >= 0);
```

### 4.2 业务触发器

```sql
-- 自动更新 updated_at
CREATE OR REPLACE FUNCTION core.update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_users_updated_at
    BEFORE UPDATE ON core.users
    FOR EACH ROW EXECUTE FUNCTION core.update_updated_at();

CREATE TRIGGER trg_conversations_updated_at
    BEFORE UPDATE ON core.conversations
    FOR EACH ROW EXECUTE FUNCTION core.update_updated_at();
```

### 4.3 数据验证

| 验证项 | 规则 | 实现方式 |
|--------|------|----------|
| 邮箱格式 | RFC 5322标准 | 应用层验证 |
| 密码强度 | 最少8位，包含大小写字母和数字 | bcrypt加密 |
| 用户名 | 3-50字符，字母数字下划线 | CHECK约束 |
| Token计数 | 非负整数 | CHECK约束 |

## 五高五标五化五维体现

### 五高

- **高可用**：所有表使用UUID主键，支持分布式部署；关键表添加冗余索引
- **高性能**：索引覆盖常用查询路径；JSONB字段支持灵活查询；分区策略支持大规模数据
- **高安全**：敏感字段加密存储；RBAC权限模型；审计日志完整记录
- **高扩展**：Schema设计支持水平分表；JSONB字段支持灵活扩展
- **高智能**：支持向量存储（pgvector扩展）；AI模型配置动态化

### 五标

- **标准化**：统一命名规范（snake_case）；统一数据类型；统一时间格式（TIMESTAMPTZ）
- **规范化**：符合数据库范式设计；建立完善的索引策略；定义清晰的关系模型
- **自动化**：自动时间戳更新；自动审计记录；自动数据清理
- **可视化**：ER图清晰展示实体关系；数据字典完整描述；监控仪表盘实时展示
- **智能化**：智能索引推荐；自动性能优化建议；异常检测告警

### 五化

- **流程化**：数据流转清晰；状态机定义明确；业务规则文档化
- **数字化**：全链路数据记录；量化指标追踪；数字化决策支持
- **生态化**：开放API接口；支持多模型集成；插件化架构设计
- **工具化**：数据迁移工具；性能分析工具；备份恢复工具
- **服务化**：微服务架构支持；API服务化；数据即服务

### 五维

- **时间维**：所有表记录创建和更新时间；支持时间范围查询；历史数据归档
- **空间维**：用户地理位置支持；多区域数据部署；CDN加速
- **属性维**：JSONB支持灵活属性；标签系统；元数据管理
- **事件维**：审计日志记录所有事件；事件溯源支持；消息队列集成
- **关联维**：清晰的实体关系；多级关联查询；图数据库扩展
