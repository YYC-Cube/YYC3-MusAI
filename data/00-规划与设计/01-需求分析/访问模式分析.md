## 二、查询模式分析

### 2.1 按操作类型分类

#### 读操作 (SELECT)

| 查询类型 | 频率 | 典型SQL | 索引需求 | 性能要求 |
|----------|------|---------|----------|----------|
| **单行查询** | 极高 | `SELECT * FROM users WHERE id = ?` | PRIMARY KEY | < 1ms |
| **唯一索引查询** | 极高 | `SELECT * FROM users WHERE email = ?` | UNIQUE INDEX | < 1ms |
| **外键查询** | 高 | `SELECT * FROM conversations WHERE user_id = ?` | INDEX | < 10ms |
| **分页查询** | 高 | `SELECT * FROM messages WHERE conversation_id = ? ORDER BY created_at DESC LIMIT 20 OFFSET ?` | 复合索引 | < 50ms |
| **关联查询** | 中 | `SELECT ... FROM users JOIN user_roles JOIN roles` | 多表索引 | < 100ms |
| **聚合查询** | 低 | `SELECT COUNT(*), AVG(tokens) FROM messages WHERE created_at > ?` | 时间索引 | < 500ms |

#### 写操作 (INSERT/UPDATE/DELETE)

| 操作类型 | 频率 | 典型SQL | 锁策略 | 性能要求 |
|----------|------|---------|--------|----------|
| **单行插入** | 高 | `INSERT INTO messages (...) VALUES (...)` | 行锁 | < 10ms |
| **批量插入** | 中 | `INSERT INTO messages (...) VALUES (...), (...), ...` | 批量锁 | < 100ms |
| **单行更新** | 中 | `UPDATE users SET last_login_at = ? WHERE id = ?` | 行锁 | < 5ms |
| **批量更新** | 低 | `UPDATE messages SET ... WHERE created_at < ?` | 范围锁 | < 500ms |
| **级联删除** | 低 | `DELETE FROM conversations WHERE id = ?` | CASCADE | < 500ms |

## 三、性能优化策略

### 3.1 索引策略

#### 核心索引配置

```sql
-- users 表索引
CREATE UNIQUE INDEX idx_users_email ON core.users(email);
CREATE UNIQUE INDEX idx_users_username ON core.users(username);
CREATE INDEX idx_users_status ON core.users(status) WHERE status != 'deleted';
CREATE INDEX idx_users_created_at ON core.users(created_at DESC);

-- conversations 表索引
CREATE INDEX idx_conversations_user_id ON core.conversations(user_id);
CREATE INDEX idx_conversations_created_at ON core.conversations(created_at DESC);
CREATE INDEX idx_conversations_user_created ON core.conversations(user_id, created_at DESC);

-- messages 表索引
CREATE INDEX idx_messages_conversation_id ON core.messages(conversation_id);
CREATE INDEX idx_messages_created_at ON core.messages(created_at DESC);
CREATE INDEX idx_messages_conv_created ON core.messages(conversation_id, created_at DESC);
CREATE INDEX idx_messages_tokens ON core.messages(tokens) WHERE tokens IS NOT NULL;
```

### 3.2 查询优化

#### 慢查询优化示例

```sql
-- 优化前：全表扫描
SELECT * FROM messages 
WHERE conversation_id = ? 
ORDER BY created_at DESC 
LIMIT 20;

-- 优化后：使用复合索引
-- 创建索引：CREATE INDEX idx_messages_conv_created ON messages(conversation_id, created_at DESC)
-- 执行计划：Index Scan Backward using idx_messages_conv_created
```

```sql
-- 优化前：使用OFFSET分页性能差
SELECT * FROM messages 
WHERE conversation_id = ? 
ORDER BY created_at DESC 
LIMIT 20 OFFSET 1000;

-- 优化后：使用游标分页
SELECT * FROM messages 
WHERE conversation_id = ? AND created_at < ?
ORDER BY created_at DESC 
LIMIT 20;
```

### 3.3 缓存策略

#### Redis缓存设计

| 缓存键 | 缓存内容 | TTL | 更新策略 |
|--------|----------|-----|----------|
| `user:{id}` | 用户信息 | 3600s | 更新时删除 |
| `user:email:{email}` | 用户ID | 3600s | 更新时删除 |
| `conversation:{id}` | 会话信息 | 1800s | 更新时删除 |
| `conversation:{id}:messages` | 最近20条消息 | 300s | 新消息时删除 |
| `user:{id}:conversations` | 用户会话列表 | 300s | 新建会话时删除 |

#### 缓存伪代码

```python
def get_user_with_cache(user_id: str):
    cache_key = f"user:{user_id}"
    
    # 1. 先查缓存
    user = redis.get(cache_key)
    if user:
        return user
    
    # 2. 缓存未命中，查数据库
    user = db.query("SELECT * FROM users WHERE id = ?", user_id)
    
    # 3. 写入缓存
    redis.setex(cache_key, 3600, user)
    
    return user

def update_user(user_id: str, data: dict):
    # 1. 更新数据库
    db.execute("UPDATE users SET ... WHERE id = ?", user_id, data)
    
    # 2. 删除缓存
    redis.delete(f"user:{user_id}")
    redis.delete(f"user:email:{data['email']}")
```

### 4.2 事务策略

```sql
-- 短事务：适用于高并发场景
BEGIN;
UPDATE users SET last_login_at = NOW() WHERE id = ?;
COMMIT;

-- 中等事务：适用于业务逻辑
BEGIN;
INSERT INTO conversations (...) VALUES (...);
INSERT INTO messages (...) VALUES (...);
UPDATE user_stats SET conversation_count = conversation_count + 1 WHERE user_id = ?;
COMMIT;

-- 长事务：避免使用，考虑拆分
-- 不推荐：BEGIN; ... (大量操作) ...; COMMIT;
```

### 4.3 锁等待优化

```sql
-- 设置锁等待超时
SET lock_timeout = '5s';

-- 使用SELECT FOR UPDATE SKIP LOCKED避免阻塞
SELECT * FROM messages 
WHERE conversation_id = ? 
AND status = 'pending'
FOR UPDATE SKIP LOCKED
LIMIT 10;
```

## 五、读写分离方案

### 5.1 读写路由规则

| 操作类型 | 路由目标 | 示例 |
|----------|----------|------|
| **读操作** | 从库 | SELECT查询、报表查询 |
| **写操作** | 主库 | INSERT、UPDATE、DELETE |
| **强一致性读** | 主库 | 用户登录、权限验证 |
| **事务操作** | 主库 | 涉及多表操作 |

### 5.2 读写分离实现

```python
class DatabaseRouter:
    def __init__(self):
        self.master_pool = create_pool(MASTER_CONFIG)
        self.slave_pool = create_pool(SLAVE_CONFIGS)
    
    def get_connection(self, read_only: bool = False):
        if read_only:
            return self.slave_pool.get_connection()
        else:
            return self.master_pool.get_connection()

# 使用示例
router = DatabaseRouter()

# 写操作使用主库
with router.get_connection() as conn:
    conn.execute("INSERT INTO messages ...")

# 读操作使用从库
with router.get_connection(read_only=True) as conn:
    result = conn.query("SELECT * FROM messages ...")
```
