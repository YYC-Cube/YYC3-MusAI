## 一、业务需求分析

### 1.1 核心需求

| 需求类别 | 具体需求 | 优先级 |
|----------|----------|--------|
| **功能需求** | 关系型数据存储、事务支持、复杂查询 | 高 |
| **性能需求** | 高并发读写、低延迟、高吞吐 | 高 |
| **扩展需求** | 水平扩展、垂直扩展、分库分表 | 高 |
| **可靠性** | 数据一致性、故障恢复、备份恢复 | 高 |
| **安全性** | 访问控制、数据加密、审计日志 | 高 |
| **成本** | 开源免费、运维成本低 | 中 |

### 1.2 数据特征

| 数据类型 | 特征 | 存储要求 |
|----------|------|----------|
| **用户数据** | 结构化、读多写少、关系复杂 | 关系型数据库 |
| **对话数据** | 半结构化、读写均衡、增长快 | 关系型数据库 |
| **消息数据** | 大文本、写多读少、时间序列 | 关系型+时间序列 |
| **审计日志** | 高写入、只追加、查询少 | 时序数据库 |
| **向量数据** | 高维向量、相似度搜索 | 向量数据库 |

### 4.1 版本选择

| 版本 | 发布时间 | LTS状态 | 推荐度 | 说明 |
|------|----------|---------|--------|------|
| PostgreSQL 17 | 2023-09 | Current | ⭐⭐⭐ | 最新特性，性能最优 |
| PostgreSQL 16 | 2023-09 | LTS | ⭐⭐⭐⭐⭐ | 稳定可靠，推荐使用 |
| PostgreSQL 15 | 2022-10 | LTS | ⭐⭐⭐⭐ | 长期支持，生产环境 |
| PostgreSQL 14 | 2021-09 | LTS | ⭐⭐⭐ | 接近EOL，不推荐 |

**推荐：PostgreSQL 16 LTS**

### 4.2 核心参数配置

```conf
# postgresql.conf

# 连接配置
listen_addresses = '*'
port = 5432
max_connections = 500
superuser_reserved_connections = 3

# 内存配置
shared_buffers = 16GB              # 系统内存的25%
effective_cache_size = 48GB         # 系统内存的75%
work_mem = 32MB
maintenance_work_mem = 1GB

# WAL配置
wal_level = replica
max_wal_size = 4GB
min_wal_size = 1GB
checkpoint_completion_target = 0.9
wal_buffers = 16MB

# 查询优化
random_page_cost = 1.1
effective_io_concurrency = 200
max_worker_processes = 16
max_parallel_workers_per_gather = 4
max_parallel_workers = 16
max_parallel_maintenance_workers = 4

# 日志配置
log_destination = 'stderr'
logging_collector = on
log_directory = '/var/log/postgresql'
log_filename = 'postgresql-%Y-%m-%d_%H%M%S.log'
log_min_duration_statement = 1000    # 记录超过1秒的查询
log_line_prefix = '%t [%p]: [%l-1] user=%u,db=%d,app=%a,client=%h '

# 统计配置
shared_preload_libraries = 'pg_stat_statements'
pg_stat_statements.max = 10000
pg_stat_statements.track = all
```

## 五、备份恢复方案

### 5.1 备份策略

| 备份类型 | 频率 | 保留期 | 存储位置 | 用途 |
|----------|------|--------|----------|------|
| **全量备份** | 每日 | 30天 | 对象存储 | 完整恢复 |
| **增量备份** | 每小时 | 7天 | 对象存储 | 快速恢复 |
| **WAL归档** | 实时 | 7天 | 对象存储 | 点恢复 |
| **逻辑备份** | 每周 | 90天 | 对象存储 | 数据迁移 |

### 5.2 备份脚本

```bash
#!/bin/bash
# backup.sh - PostgreSQL备份脚本

# 配置
PG_HOST="localhost"
PG_PORT="5432"
PG_USER="postgres"
PG_DATABASE="yyc3_aify"
BACKUP_DIR="/backup/postgresql"
S3_BUCKET="s3://yyc3-backups/postgresql"

# 创建备份目录
mkdir -p $BACKUP_DIR/{full,incremental,wal}

# 全量备份（使用pg_dump）
pg_dump -h $PG_HOST -p $PG_PORT -U $PG_USER \
    -F c -f $BACKUP_DIR/full/yyc3_$(date +%Y%m%d).dump \
    $PG_DATABASE

# WAL归档（使用pg_archivebackup）
pg_basebackup -h $PG_HOST -p $PG_PORT -U $PG_USER \
    -D $BACKUP_DIR/wal -F t -z -P \
    -x -c fast

# 上传到S3
aws s3 sync $BACKUP_DIR $S3_BUCKET/$(date +%Y/%m/%d)

# 清理过期备份
find $BACKUP_DIR/full -name "*.dump" -mtime +30 -delete
find $BACKUP_DIR/incremental -name "*.diff" -mtime +7 -delete
```

### 5.3 恢复脚本

```bash
#!/bin/bash
# restore.sh - PostgreSQL恢复脚本

# 配置
BACKUP_FILE="/backup/postgresql/full/yyc3_20260225.dump"
PG_HOST="localhost"
PG_PORT="5432"
PG_USER="postgres"
PG_DATABASE="yyc3_aify"

# 停止应用服务
systemctl stop yyc3-api

# 恢复数据库
pg_restore -h $PG_HOST -p $PG_PORT -U $PG_USER \
    -d postgres -c -j 4 $BACKUP_FILE

# 重启应用服务
systemctl start yyc3-api

# 验证数据
psql -h $PG_HOST -p $PG_PORT -U $PG_USER -d $PG_DATABASE \
    -c "SELECT COUNT(*) FROM core.users;"
```
